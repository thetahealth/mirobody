# 遺伝子データ

消費者向け遺伝子検査の書き出しファイル、または単一サンプルの VCF をアップロードすると、選択した人の記録にバリアントコールが保存されます。遺伝子検査の報告書は通常の文書として扱われ、生の遺伝子型ファイルは別のインポートと照会の流れを使います。

## 対応するアップロード

インポーターは、23andMe・AncestryDNA・MyHeritage・FTDNA・WeGene を含む、対応するテキストおよび CSV の書き出しファイルを認識します。VCF と対応する圧縮形式にも対応します。複数の遺伝子型ファイルを含む ZIP や、複数サンプルの VCF は、どのファイルまたはサンプルを使うべきか判断できないため拒否されます。

**データ**ページにインポート状況が表示されます。インポートに成功すると新しいセットが有効になり、再アップロードすると有効なコレクションが置き換わります。インポートに失敗した場合は、それまでの有効なセットがそのまま使えます。

## 照会

| ツール | 用途 |
| --- | --- |
| `query_genetic_data` | rsID・遺伝子・範囲を指定した染色体領域でバリアントコールを検索します。 |
| `query_pharmacogenomics` | CPIC の薬物・遺伝子カバレッジと、判定に必要な位置がそろっているかを確認します。 |

領域の照会には `GRCh37`、`GRCh38`、または明示的に `raw` の座標を使います。結果にはコールの状態と出どころの情報が残ります。対応していない、またはあいまいなコールは未解決のままになり、位置が存在しない場合や `no_call` は正常な結果ではありません。

薬理ゲノムのカバレッジは、表現型や処方の助言を確定するものではありません。現在のツールは、不完全なアレイデータからスター対立遺伝子を推定するのではなく、表現型に `not_determined` を返します。まれなバリアントコールが疾患の診断に変換されることはありません。

## エクスポート

有効なコレクションは VCF として、または選択した rsID を FHIR の variant observation としてエクスポートできます。自分のアカウントのトークンを使ってください。[データのエクスポート](https://docs.mirobody.ai/ja/deployment/export)を参照してください。
座標系の扱い、対応するレイアウト、照会の例は[遺伝子データリファレンス](../genetics.md)（英語）にあります。
