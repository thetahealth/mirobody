# 数据标准化

同一项检查，三份报告可能印成三个样子：`LDL-C 2.48 mmol/L`、
`低密度脂蛋白胆固醇 96 mg/dL`、`LDL Cholesterol 101 mg/dL`。要把它们画进同一条趋势，
先得判断这是同一项测量，再把数值换到可以比较的基准上。标准化做的就是这件事：
在你自己的机器上离线完成，不需要模型 API Key；判断不了的时候，留空并说明原因，不猜。

## 一条读数经过的七步

| 步骤 | 做什么 | 例子 |
| --- | --- | --- |
| 1. 原样保留 | 名称、数值、单位、参考范围、高低标记按报告原样存下。后面每一步的结果都存在旁边，不覆盖原文 | `LDL-C` · `2.48` · `mmol/L` · `<3.4` |
| 2. 读懂数值 | 判断数值是数字、分级标记、文字结论还是一段描述；保留比较符；单位规范成 UCUM | `<0.5 mg/L` 记为 0.5 和 `<`；`阴性` 是文字结论；`120/80` 是描述，不当成一个数 |
| 3. 拦下不可能的值 | 没有时间、时间在未来、百分比超过 100 的读数不入库，记下原因，不替它补值 | 报告上找不到日期，会请你补日期，而不是记成今天 |
| 4. 认出是哪项检查 | 名称折叠后查随包词表：先查你确认过的编码，再查项目手写的词条和中文译名，最后查 LOINC 自带的 21 种语言名称 | `血红蛋白`、`血紅素`、`ヘモグロビン`、`hemoglobin` 都落到 `718-7` |
| 5. 由读数挑出具体编码 | LOINC 把单位类型写进了编码。印的单位决定是质量浓度还是摩尔浓度，`阴性` 这类结论决定用定性编码；单位不会把读数改到别的标本上 | `LDL-C 2.48 mmol/L` → `22748-8`（摩尔）；`96 mg/dL` → `13457-7`（质量）；`尿糖 阴性` → `2349-9`（定性） |
| 6. 编码，或者不编 | 每条读数的结果是**已编码**、**待确认**或**不编码**之一，原因和结果一起存下 | `血脂` 是一组检查，不编码；`血糖(HbA1c)` 是两项检查，等你确认 |
| 7. 归入同一序列 | 只差在单位类型或检测方法的编码归为一个序列，数值经摩尔质量换算后比较 | 2.48 mmol/L、96 mg/dL、101 mg/dL 落进同一条 LDL 序列，约 2.5–2.6 mmol/L |

回答问题时读的是序列，不是报告上的原名：三份报告画出来是一条线，回答里的每个数字都能点回它所在的那一行和原文件。

## 读数的来源

| 来源 | 怎样进入第 1 步 | 哪里用到模型 |
| --- | --- | --- |
| 化验单、体检报告（PDF、照片、表格） | 先用规则读表格，规则读不了的行才交给模型 | 读页面。模型照抄报告上的名称，从不给编码 |
| 穿戴设备、Apple Health | 每个厂商字段按固定的对照表换成目录里的单位 | 不用 |
| 健康日记里的一句话 | `头疼，血压150/95` 拆成一条主诉和两条读数 | 拆句和判断类型。编码来自词表 |
| HTTP API | 按报告原样传名称、数值和单位 | 不用 |

主诉和诊断走另一套词表 ICPC-3：`头疼` 是 `NS01`，`高血压` 是 `KD73`。主诉不会被编成化验项目。

## 未编码的读数

没编码的读数照样保存，也照样能被查询和回答。它按报告上的原名单独成一个序列，不会混进别的检查。

| 结果 | 常见原因 | 你可以做什么 |
| --- | --- | --- |
| 待确认 | 名称不认识；一个名称里有两项检查；缺单位或单位不认识；单位和这项检查的所有编码都对不上 | 确认一次编码，所有印着这个名称的读数会一起重新编码：`POST /api/v1/health-indicators/confirm-code`（[文件处理](../file-processing.md)，英文） |
| 不编码 | 名称是一个类别或一组检查（`血脂`、`lipid panel`），或者这一行是笔记而不是测量 | 不用处理，这是有意的 |

常见的名称认不出来，欢迎反馈。新语言、新医院的写法就是这样一行行补进来的，见[补充词表](#补充词表)。

## 试用

只查名称，在终端里运行，首次下载后离线可用：

```bash
uvx --python 3.12 mirobody resolve LDL-C 低密度脂蛋白胆固醇 血脂
```

查一条完整读数，在 Python 里得到 FHIR Observation，其中记着编码是怎么选出来的：

```python
from mirobody.engine import resolve_reading, standardize_reading

resolve_reading("LDL-C", "2.48", "mmol/L").loinc   # '22748-8'  单位选了摩尔浓度
resolve_reading("LDL-C", "96", "mg/dL").loinc      # '13457-7'  这里是质量浓度
resolve_reading("albumin", "30", "mg/24h").loinc   # ''  血清的名称配了尿液的单位

standardize_reading("LDL-C", "2.48", "mmol/L")     # 编码、数值和决策记录
```

## 边界

- **只按词表匹配。** 词表里没有的名称返回「未解析」，不给最接近的编码。认得的写法靠一行行补充，不靠猜。
- **只编测量，不编厂商评分。** Body Battery、压力分数是某家公司的公式，没有 LOINC 编码。
- **编码说明测的是什么，不说明正不正常。** 偏高偏低以报告上印的参考范围和标记为准。
- **词表有版本。** `mirobody.BUNDLE_VERSION` 写明 LOINC 版本和切分日期。升级后运行 `mirobody recode`，已存的读数会按新词表重新编码，每次变化都留有记录。

## 补充词表

运行 `mirobody resolve "<报告上印的名称>"`。结果不对或为空时，
[提交这个名称](https://github.com/thetahealth/mirobody/issues/new?template=wrong-term.yml)，
或者在 `mirobody/res/loinc/resolver_overrides.tsv` 加一行并配一个测试用例。
俄语、爱沙尼亚语和土耳其语报告的写法就是这样补进来的。

词表的范围、许可、实测数据，以及每一步对应的代码，见[标准化技术参考](../standardization.zh-CN.md)。
