# 健康データを標準化する

同じ検査でも、3つの報告が3通りの書き方で印字することがあります。`LDL-C 2.48 mmol/L`、
`低密度脂蛋白胆固醇 96 mg/dL`、`LDL Cholesterol 101 mg/dL`。これらが同じ測定であり、
数値をどう比較するかを何かが決めない限り、1本のグラフにはまとまりません。標準化とは、
その決定です。あなたのマシン上でオフラインで動き、モデルの API キーを必要とせず、
決められないときは、推測せずにその測定値をコードなしのままにして理由を示します。

## 測定値がたどる手順

| 手順 | 内容 | 例 |
| --- | --- | --- |
| 1. 印字どおりに残す | 名称・数値・単位・基準範囲・フラグを、印字されたとおりに保存します。これ以降の結果はすべてその横に導出され、元の値を上書きすることはありません。 | `LDL-C` · `2.48` · `mmol/L` · `<3.4` |
| 2. 数値を読み取る | 数値を、数・段階的な記号・ラベル・テキストのいずれかに分類します。比較演算子は保持し、単位は UCUM に正規化します。 | `<0.5 mg/L` は `<` 付きの 0.5、`阴性` はラベル、`120/80` は数ではなくテキストです |
| 3. ありえない値を拒む | 時刻がない、未来の時刻、100 を超える割合の測定値は保存しません。理由とともに件数に数え、値を埋めることはしません。 | 日付のない報告には日付の入力を求め、今日の日付にはしません |
| 4. 検査項目を見つける | 畳み込んだ名称を同梱の語彙で検索します。まずあなたが確認済みのコード、次にプロジェクトが手作業で追加した行と中国語訳、最後に LOINC 自身が持つ21言語の名称の順です。 | `血红蛋白`、`血紅素`、`ヘモグロビン`、`hemoglobin` はすべて `718-7` に到達します |
| 5. 読み取った値にコードを選ばせる | LOINC は単位の種類をコードに組み込んでいます。印字された単位が質量濃度かモル濃度かを決め、`阴性` のような語が定性コードを決めます。単位によって測定値が別の検体に移ることはありません。 | `LDL-C 2.48 mmol/L` → `22748-8`（モル）、`96 mg/dL` → `13457-7`（質量）、`尿糖 阴性` → `2349-9`（定性） |
| 6. 決めるか、見送る | 各測定値は**コード付き**・**要確認**・**コードなし**のいずれかになり、理由もあわせて保存されます。 | `血脂` はパネル名のためコードなし。`血糖(HbA1c)` は2つの検査を指すため確認を求めます |
| 7. 系列にまとめる | 単位の種類や測定方法だけが異なるコードは1つの系列を共有し、数値はモル質量を介して比較します。 | 2.48 mmol/L、96 mg/dL、101 mg/dL は1つの LDL 系列にまとまり、約 2.5〜2.6 mmol/L になります |

回答はその系列を読み取り、元の名称は読みません。3つの報告にまたがる推移が1本の線になり、
回答の中のどの数値も、元の行とその出どころのファイルまでたどれます。

## 測定値の出どころ

| 出どころ | 手順1に届くまで | モデルが関わる部分 |
| --- | --- | --- |
| 検査報告（PDF・写真・表計算） | まず規則で表を読み取り、規則が読めなかった行だけモデルが読みます。 | ページを読み取る部分。モデルは印字された名称をそのまま写すだけで、コードを選ぶことはありません。 |
| ウェアラブルまたは Apple Health | 各ベンダーのフィールドを、固定の対照表でカタログの単位に変換します。 | なし |
| 健康日記の一文 | `头疼，血压150/95` は主訴1件と測定値2件に分けられます。 | 文を分割し、種類を判定する部分。コードは語彙から来ます。 |
| HTTP API | 名称・数値・単位を印字どおりに送信します。 | なし |

主訴と診断は別の語彙、ICPC-3 を使います。`头疼` は `NS01`、`高血压` は `KD73` です。
主訴が検査としてコード化されることはありません。

## コードが付かない測定値

コードが付かない測定値も保存され、質問に答える材料になります。印字されたままの名称で独自の系列にとどまり、ほかの検査と混ざることはありません。

| 結果 | よくある理由 | できること |
| --- | --- | --- |
| 要確認 | 名称が未知。名称が2つの検査を指す。単位がない、または未知。単位がその検査項目のどのコードとも矛盾する | 一度コードを確認すれば、その名称で印字された測定値がすべて再コードされます：`POST /api/v1/health-indicators/confirm-code`（[ファイル処理](../file-processing.md)、英語） |
| コードなし | 名称がカテゴリやパネルを指す（`血脂`、`lipid panel`）。または行がメモであって測定ではない | 何もしません。意図的な扱いです |

よく使われる名称が認識されない場合は報告してください。新しい言語や病院ごとの表記は、
そうして追加されています（[語彙を改善する](#語彙を改善する)を参照）。

## 試してみる

名称だけなら、ターミナルから、初回ダウンロード後はオフラインで使えます。

```bash
uvx --python 3.12 mirobody resolve LDL-C 低密度脂蛋白胆固醇 血脂
```

読み取り1件をまるごと扱うなら、Python で FHIR Observation として、コードがどう選ばれたかも記録されます。

```python
from mirobody.engine import resolve_reading, standardize_reading

resolve_reading("LDL-C", "2.48", "mmol/L").loinc   # '22748-8'  単位がモル濃度を選んだ
resolve_reading("LDL-C", "96", "mg/dL").loinc      # '13457-7'  ここでは質量濃度
resolve_reading("albumin", "30", "mg/24h").loinc   # ''  血清の名称に尿の単位が付いている

standardize_reading("LDL-C", "2.48", "mmol/L")     # コード、数量、判定の記録
```

## 限界

- **語彙に基づく照合です。** 語彙にない名称は常に `unresolved` を返し、最も近い候補を返すことはありません。認識率は行を追加することで伸び、推測では伸びません。
- **測定値にコードを付け、ベンダーのスコアには付けません。** Body Battery やストレススコアは一企業の独自の計算式であり、LOINC コードを持ちません。
- **コードが示すのは何を測ったかであり、正常かどうかではありません。** 高い・低いの判定は、
  報告書に印字された範囲とフラグに基づきます。
- **語彙にはバージョンがあります。** `mirobody.BUNDLE_VERSION` が LOINC のリリースと切り出し日を示します。アップグレード後は `mirobody recode` を実行すると、保存済みの測定値が新しい語彙で再コードされ、変更はすべてコード履歴に残ります。

## 語彙を改善する

`mirobody resolve "<印字されたままの名称>"` を実行します。結果が間違っている、または空の場合は、[その語を報告する](https://github.com/thetahealth/mirobody/issues/new?template=wrong-term.yml)か、
`mirobody/res/loinc/resolver_overrides.tsv` にテストケース付きで1行追加してください。
ロシア語、エストニア語、トルコ語の報告の表記は、こうして追加されてきました。

語彙の対象範囲・ライセンス・実測データ、各手順の裏にあるコードは[標準化リファレンス](../standardization.md)（英語）にあります。
