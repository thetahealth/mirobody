# 后端 Harness 优化与 100 题评测计划

[English](2026-10-21-harness-evaluation-100.md)

> 本文记录 2026-10-21 的实现和验证。用户要求优化 harness，将评测扩展为 100 题，保留本地基因分析与 GLM-OCR-0.9B 辅助的照片、文档解析能力，并将首个可见 thinking token 计入首 token 延迟。后续已授权提交 PR。

**目标：** 将执行过程与最终答案分离，建立可复现、有足够任务多样性的本地模型 100 题产品回归。

**架构：** 继续使用唯一的 `MirobodyAgent` 及现有模型、工具事件格式，增加不含正文的 `context` 事件来报告真实摘要活动。每轮请求独立维护展示状态：原生 reasoning 立即流出，普通文本等模型步骤结束后再分类；工具步骤的叙述进入思考区，只有最终回复成为答案文本。问题和数据加载计划从固定版本的 mirobody-gen 原始数据生成，参考答案不来自被测产品的回答。分别测量首个可见 token、首段 reasoning、首次工具活动、首段答案和整轮完成时间。

**技术栈：** Python、LangGraph/deepagents、现有 HTTP 评测器、mirobody-gen `9723605`、pytest。

## 范围与约束

- 初始后端基线为 `d8463a4a`，包含 PR #159、#166、#167。提交 PR 前已 rebase 到最新 `origin/main` 的 `d4468653`，同时整合 PR #168。
- 不增加第二套 harness，不新增公共 MCP 工具，测试材料不含真实健康记录。
- 对支持的模型协议请求原生 thinking。工具事件是真实工作反馈，不伪造模型思考；模型没有返回可见 reasoning 时，这一缺失仍可被测量。
- OCR、信息提取等辅助模型保持独立策略，不被聊天模型的 thinking 策略强制覆盖。当前本地 OCR 模型为 **GLM-OCR-0.9B**；不能把文档文字解析能力等同于任意照片的通用视觉理解。
- 最终答案及未来语音输入不混入执行过程叙述。Reasoning 和工具活动使用独立事件进入思考面板。
- 未做的语料审计保持“未验证”；失败记录和历史评测结果保留。
- 正式计分题目恰好 **100 道：60 英文、30 简体中文、5 日文、5 繁体中文**，覆盖当前前端全部四种语言。
- 多轮题复用同一会话。一道重型长上下文追问题允许最多 16 次额外的、明确记录的数据读取压力请求；只有真正完成两次自动摘要之后，才进行记忆保持评分。
